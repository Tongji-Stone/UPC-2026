# 三台电脑协作约定

## 分工

- 电脑 A（本机）：项目整合、反演、概率预测、最终实验和报告。
- 电脑 B：正向物理仿真、气动系数和模型退化。
- 电脑 C：公开数据、数据处理、独立验证与评价指标。

各自阅读仓库根目录 `Agents.md`、`赛题.md` 和 `协作任务/完整任务书.md`。完整任务书是需求依据；具体分工以各自任务卡为准。优先完成可运行的最小版本，及时交接，避免等所有功能完成才合并。

## 分支和目录

建议分别使用 `codex/integration`、`codex/physics`、`codex/data-validation`；先从共同的最新 `main` 建立分支。使用独立分支提交，提交信息简洁中文。推送、拉取及合并按团队约定进行。

建议在仓库根目录建立 Python 项目：`src/football/`、`tests/`、`configs/`、`scripts/`、`data/`、`results/` 和 `docs/`。B 主要修改 `src/football/physics/` 和相关测试；C 主要修改 `src/football/data/`、`src/football/evaluation/` 和相关测试；A 负责 `src/football/inference/`、整合脚本和公共配置。需要修改公共文件时先说明，减少冲突。各自可以先独立实现，具体接口以实际交接为准，整合时适配。

## 数据与接口约定

- 国际单位制：时间秒、长度米、速度米每秒、角速度弧度每秒；`x` 指向预测平面，`y` 为横向，`z` 向上；坐标为球心位置。
- 观测使用时间数组和对应的 N×3 位置数组；需要时附加测量误差。轨迹及事件须带时间、三维位置、速度，事件区分穿越平面与落地。各模块保留原始观测时间，不使用未来帧构造过去的输入。
- 预测应提供落点样本或概率分布、事件状态及所用假设。概率统计区分落地、未穿越、球心在门框内和足球完整通过等情况，并写明分母。
- 具体 Python 类型、命名和文件格式由 A 与 B、C 交接时确认；不要在尚未共同确认的细节上等待。
- 原始数据与处理结果分开，记录来源、许可、下载日期、坐标和单位转换。大型原始数据不要直接提交仓库，提供获取与处理说明。
- 随机实验记录种子、配置和版本；计算与绘图分离，保存中间结果。

## 交接

每完成一个可运行阶段，提交并告知 A：分支与提交号、完成内容、运行命令、测试结果、接口及已知问题。未做或未验证的功能明确标注。遇到依赖其他模块时，可用小型合成数据或临时适配层继续工作，交接时说明。

优先顺序：B 尽快交出重力和事件检测的最小仿真接口；A 使用它完成基础反演与两次预测；C 并行核查公开数据并建立不泄漏未来观测的验证流程。随后扩展 M5、概率分析和对比实验。
