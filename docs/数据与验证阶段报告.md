# 足球轨迹数据与验证：阶段记录

## 数据从哪里来

足球比赛的光学追踪系统会按帧记录球的位置。我们可以用前几帧推算后面的运动，再把预测与后续记录比较。数据来源、时间间隔和坐标单位必须先对齐，才能公平比较不同方法。

**DFL 七场比赛**由德国足球职业联盟授权，原始位置文件包括球的 X、Y、Z，以及帧号 N、时间戳 T 和比赛状态；位置按米处理。相机为 25 Hz，帧间隔通常为 0.04 秒。数据采用 CC BY 4.0，使用时注明 DFL 并引用 [Bassek 等人的论文](https://www.nature.com/articles/s41597-025-04505-y)；[官方配套代码](https://github.com/spoho-datascience/idsse-data)链接了 [Figshare 原始数据](https://doi.org/10.6084/m9.figshare.28196177)。本机访问 Figshare API 未得到有效 JSON，因此从[公开镜像目录](https://huggingface.co/datasets/pysport/idsse-data)下载了 J03WOH 单场位置 XML（348,945,715 字节），未下载视频。

**ball3d** 的 [数据说明](https://github.com/lukaszgrad/ball3d/blob/main/DATA.md)指出，`track/ball_3d-gt.csv` 包含 `file_name`、`track_id`、`x,y,z` 等列；位置单位为分米，帧率读取同一片段的 `sequence_metadata.json`，时间为帧号除以实际帧率。其标注与三角测量轨迹采用 CC BY-NC-SA 4.0，视频另有限制。数据在说明中所列的 Google Drive 文件夹；文件大小和实际可访问性尚未核实。

**SoccerNet-GAR** 的[数据页面](https://huggingface.co/datasets/OpenSportsLab/SoccerNet-GAR)要求申请访问，获准后签署个性化保密协议。其完整追踪表示为 30 fps，稀疏版采样频率不同，须按实际版本处理。本阶段未申请访问。

## 本次建立的方法

公共输入是以秒为单位的时间数组和以米为单位的 N×3 球心位置数组。`football.data.validation` 检查有限数值、严格递增时间与速度上限，提供 ball3d 分米转换、平面坐标旋转、早期观测截取和后续轨迹穿越平面的线性插值。方向应仅由早期已观测帧确定，若用于真实比赛的固定球门则须用球门方向。

25 Hz 的前 0.05 秒取 0、0.04 秒两帧；前 0.10 秒取 0、0.04、0.08 秒三帧。样本选择应预先固定，例如按比赛、上半场、轨迹段和起始帧升序，筛选完整、连续、空中飞行且后续穿越距起点 11 米的片段，并保存全部入选和排除原因。预测平面穿越点用截断后的后续两帧插值；这些帧只用作答案。普通飞行轨迹的平面称为虚拟预测平面。

`football.evaluation.metrics` 提供二维落点误差均值、中位数、90% 分位数、经验预测分布的能量评分和区域覆盖率。统计均以具有真实穿越且模型也给出穿越的案例为分母；另须报告全部候选数、真实未穿越数、预测未穿越数和共同有效数。能量评分越小越好，单位为米；覆盖率由调用者根据既定区域判断是否覆盖后传入。运行时间由调用预测器的实验脚本计时。

## 验证与下一步

运行 ` $env:PYTHONPATH='src'; python -m pytest tests/test_data_validation.py -q `，得到 2 项测试通过。测试用合成直线检查帧截断、穿越插值、单位转换及评分。

对 J03WOH 实际比赛数据，按原始顺序选取第一个符合以下条件的片段：连续 21 帧、间隔 0.04 秒、比赛进行中、球高在 0.3–15 米、逐帧速度在 2–45 m/s、初始水平位移至少 0.2 米，且在 0.10 秒后穿越前方 11 米的虚拟平面。筛选使用完整片段判断是否满足验证条件，预测本身只使用截断前观测。选中上半场第 10062 帧开始的片段，方向由前两帧确定，平面穿越点由后续两帧插值。该筛选用于取得可比较答案，未来统计比较须使用同一固定样本清单。

最简单的匀速外推，用首帧到最后一帧估计速度；用前 0.04 秒观测时二维误差为 **0.334 米**，用前 0.08 秒时为 **0.212 米**。这是一条普通飞行轨迹，其虚拟平面穿越高度约 5.45 米。计算结果和 21 帧样本保存在 `results/dfl_example/`。[论文](https://www.nature.com/articles/s41597-025-04505-y.pdf) Box 3 将 Z 描述为球高，却没有明确写出 Z 的单位；论文引用的 [floodlight DFL 解析器](https://github.com/floodlight-sports/floodlight/blob/main/floodlight/io/dfl.py)未读取 Z。本示例暂假设 Z 以米计，尚需结合原始数据规范确认高度单位、定义和测量质量。

PowerShell 复现命令（先从镜像下载 `DFL_04_03_positions_raw_observed_DFL-COM-000002_DFL-MAT-J03WOH.xml` 到 `data/raw/J03WOH.xml`）：

```powershell
python scripts/extract_dfl_ball.py data/raw/J03WOH.xml data/processed/J03WOH_ball.csv
$env:PYTHONPATH='src'
python scripts/dfl_example.py data/processed/J03WOH_ball.csv
```

下一步扩充固定样本清单、排查碰撞和异常球高，并接入统一预测器进行比较。

同一片段还运行了 `python scripts/dfl_compare.py`，用各模型拟合窗口内初速度：

| 模型 | 0.05 秒窗口误差（米） | 0.10 秒窗口误差（米） |
|---|---:|---:|
| M0 匀速 | 0.334 | 0.236 |
| M1 重力 | 0.906 | 0.808 |
| M2 匀加速度 | 观测不足 | 0.991 |
| M3 重力与阻力 | 1.002 | 0.896 |
| M4 重力、阻力与旋转力 | 1.008 | 0.952 |

M0、M1、M3、M4 的初速度按窗口内全部点拟合；M4 假设竖直轴自旋 30 rad/s、升力系数 0.2，其余模型自旋为零。M2 在三帧时用插值求解，检查预测时刻之后是否先于平面穿越触地。表中 M0 的 0.10 秒结果与上面的首尾两帧速度基线不同，原因是这里用三帧共同拟合初速度。比较使用同一个样本和预测平面；这些模型均报告成功穿越。全部结果保存在 `results/dfl_example/model_comparison.json`。

## 30 条真实比赛片段的批量比较

单个片段只能展示计算过程。为观察不同轨迹上的表现，程序从同一场比赛按时间顺序寻找符合上文条件的前 30 条片段；每选中一个就跳过其 21 帧，保证选中片段不重叠。整个筛选检查了 15,795 个候选起点，选中 30 个；其余按首次不满足条件计数：比赛未进行或跨半场 10,192，球高 4,621，速度 151，初始方向 248，后续没有穿越平面 553。跳过的重叠起点不计入检查总数。球高和后续穿越只用于选定可评价的片段；每个模型仅使用窗口内观测拟合，初始坐标轴由前两帧确定。

| 模型 | 0.05 秒窗口：平均／中位／90%误差（米，30 条） | 0.10 秒窗口：平均／中位／90%误差（米，27 条） |
|---|---:|---:|
| M0 | 1.023／1.023／1.992 | 0.932／0.975／1.579 |
| M1 | 0.770／0.706／0.927 | 0.685／0.654／0.825 |
| M2 | 两帧不足以计算 | 2.473／1.557／4.349 |
| M3 | 0.891／0.798／1.025 | 0.787／0.751／0.963 |
| M4 | 1.023／0.986／1.320 | 0.908／0.887／1.279 |
| M5 | 1.065／1.024／1.368 | 0.947／0.933／1.340 |

25 Hz 下，两个窗口分别只有 0、0.04 秒和 0、0.04、0.08 秒的观测。0.05 秒窗口的五个物理模型均穿越；0.10 秒窗口 M2 有 3 条未穿越，因此该列采用所有六个模型共同穿越的 27 条，方便直接比较。各模型各自的全部可用样本结果、未穿越次数、每次耗时和样本编号见 `results/dfl_benchmark/summary.json` 及 `samples_and_predictions.csv`。30 条片段均来自 J03WOH，可能存在属于同一长传或射门的相邻片段，尚未按事件分组。

M4、M5 都假设固定竖直轴自旋 30 rad/s；M4 使用固定 Cd=0.25、Cl=0.2。M5 使用物理模块中的 Linthorne–Patel 关系，Cd0=0.18；该关系在固定转速下系数也保持恒定。其余模型自旋为零。M2 用三点拟合匀加速度并检查触地事件，其他模型拟合初速度后用各自物理模型求解。所有结果中的高度以米为工作假设。

运行命令：

```powershell
$env:PYTHONPATH='src'
python scripts/dfl_benchmark.py data/processed/J03WOH_ball.csv --count 30
```

完整计算重复运行一次，360 条模型记录除运行时间外完全一致。运行时间受机器负载影响，保存在结果文件中。接下来可引入其他比赛和事件标注，并检查球是否在片段中途被触碰，以得到更独立的空中飞行样本。
